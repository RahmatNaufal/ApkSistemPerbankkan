Proyek OOP · INT BANK

Bedah Object-Oriented Programming

Empat pilar OOP tidak hanya dijelaskan, tetapi dipakai langsung oleh logika rekening di bawah ini. Gunakan simulator di halaman ini untuk melihat polimorfisme bekerja.

⚠

Hanya simulasi. Simulator ini membaca data contoh dan tidak menyentuh saldo asli, tidak menyimpan transaksi, serta tidak mengubah rekening mana pun.

01

Enkapsulasi

Data saldo dan status disembunyikan di dalam objek, sehingga hanya bisa diubah lewat method yang selalu memvalidasi aturan.

private Money balance;

public final void credit(Money amount) {
    validateCredit(amount);
    balance = balance.plus(amount);
}

Sumber: Account.java

02

Abstraksi

Kelas induk mendefinisikan kontrak umum seluruh rekening, sementara detail teknisnya diserahkan ke kelas turunan.

public abstract class Account {
    public abstract String typeName();
    protected abstract Money minimumBalance();
    protected abstract Money projectedInterest(int months);
}

Sumber: Account.java

03

Pewarisan

Tabungan, Giro, dan Deposito mewarisi aturan umum dari Account, lalu mengisi bagian yang berbeda sesuai jenisnya.

public class SavingsAccount extends Account {
    @Override public String typeName() {
        return "Tabungan";
    }
}

Sumber: SavingsAccount.java

04

Polimorfisme

Satu panggilan method menghasilkan perilaku berbeda pada tiap jenis rekening, tanpa perlu memeriksa tipenya satu per satu.

// satu panggilan, tiga perilaku
account.validateWithdraw(amount, today);
// Tabungan → saldo minimum Rp50.000
// Giro     → biaya Rp2.500
// Deposito → hanya penuh setelah jatuh tempo

Sumber: Account.java, DepositAccount.java

Peta pewarisan rekening

Account  (abstrak · template method)
├── SavingsAccount  → Tabungan   · min. Rp50.000 · bunga 3% p.a. · tanpa biaya
├── CurrentAccount  → Giro       · min. Rp0      · tanpa bunga · biaya Rp2.500
└── DepositAccount  → Deposito   · dana awal saja · bunga 5% p.a. · cair penuh saat jatuh tempo
